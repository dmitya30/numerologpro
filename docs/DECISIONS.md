# Решения проекта

Дата актуализации: 24.08.2026.

Этот документ фиксирует принятые архитектурные и продуктовые решения. Новые решения добавляются отдельными записями, а существующие не переписываются без явной причины и ссылки на заменяющее решение.

## D-001. Отказ от Ghost

Статус: принято.

Ghost выбран ошибочно для преимущественно статических продуктовых страниц. Целевой сайт создаётся как обычный набор HTML, CSS, JavaScript и локальных ресурсов без runtime-зависимости от Ghost.

Ghost-служебные механизмы, темы, API, Portal, Search, members, comments и административная часть не переносятся как функции нового сайта.

## D-002. Production на GitHub Pages

Статус: принято.

Исходный код хранится в публичном репозитории `https://github.com/dmitya30/numerologpro`. GitHub Pages используется сначала для draft QA, затем для production с пользовательским доменом `numerologpro.ru`.

Текущий VPS не используется как постоянный production после успешной миграции.

## D-003. Информационная продуктовая мультивизитка

Статус: принято.

Сайт представляет продукты и ведёт только к бесплатным точкам входа в соответствующие Telegram-боты.

С нового сайта удаляются цены, тарифы, кнопки покупки, способы оплаты, формы заказа, платёжные сценарии и другая явная коммерческая транзакционная функциональность.

## D-004. Обязательные страницы

Статус: принято.

Обязательные маршруты нового сайта: `/`, `/elyor/`, `/quantocode/`, `/oracle/`.

Блог, статья, RSS, архивы автора и тега не переносятся.

## D-005. Статус страницы `/about/`

Статус: отложено.

Страница `/about/` не является обязательной для продуктовой мультивизитки. До отдельного решения она не добавляется в основную навигацию и sitemap нового сайта.

## D-006. Юридические страницы

Статус: принято.

Старые `/privacy/`, `/consent/` и `/oferta/` не относятся к новому сайту «Тихого Дома» и не переносятся.

Юридические материалы отдельных продуктов реализованы в связанных с Telegram-ботами публикациях. Их нельзя автоматически включать в сайт или связывать с зонтичным брендом без отдельного подтверждения.

## D-007. Назначение главной

Статус: принято.

Главная представляет «Тихий Дом» как зонтичный бренд. КвантоКод имеет самостоятельную страницу `/quantocode/`, поэтому главная не должна повторять её структуру и оффер.

Новая главная проектируется на отдельном контентном и визуальном гейте.

## D-008. Пути для preview и production

Статус: принято.

Внутренние ссылки и runtime-ресурсы должны работать в project preview `https://dmitya30.github.io/numerologpro/` и после подключения `https://numerologpro.ru/`.

Относительные пути предпочтительны там, где они обеспечивают работу обоих вариантов. Canonical, Open Graph, Schema.org и sitemap проверяются отдельно и не переводятся в относительный формат механически.

## D-009. DNS cutover после QA

Статус: принято.

Домен переключается только на уже опубликованный и проверенный GitHub Pages site. До DNS cutover должны пройти технический и человеческий QA preview-версии.

После переключения проверяются apex, `www`, HTTPS, обязательные маршруты и ресурсы. VPS и Ghost сохраняются как временный fallback до завершения production QA.

## D-010. Постоянный Ghost-архив не требуется

Статус: принято.

Полный постоянный архив Ghost не является обязательным результатом проекта. Текущий работающий Ghost используется как временная страховка и источник до успешного переноса.

Удаление Ghost и отмена VPS разрешаются только после production QA и отдельного подтверждения пользователя.

## D-011. Аналитика сохраняется при статической миграции

Статус: принято.

Подтверждённые интеграции Яндекс Метрики и Google Analytics сохраняются при статической миграции без изменения идентификаторов.

Ghost-служебный Code Injection не переносится. Вопросы состава данных и consent-механизма проверяются отдельно до production cutover; это не является основанием самовольно удалять подтверждённую аналитику.

## D-012. Минимальная техническая архитектура

Статус: принято.

Для нескольких статических страниц не добавляются framework, Node.js, npm, bundler или static-site generator без подтверждённой необходимости.

Предпочтительна минимальная реализация на HTML, CSS и JavaScript с локальными ресурсами и простым GitHub Pages deployment.
## D-013. Санитизированный контекст миграции в репозитории

Статус: принято.

Проверяемые санитизированные результаты аудита временно хранятся в каталоге `migration-audit/` публичного репозитория. Это позволяет восстанавливать фактический контекст через GitHub после сжатия диалога и не зависеть только от локальной `.work/`.

Сырые HTML-снимки не публикуются автоматически. В публичную историю запрещено добавлять Ghost Content API keys, cookies, authorization headers, секреты, приватную инфраструктурную конфигурацию и необработанный Code Injection.

Удаление каталога из актуальной ветки не удаляет его из истории Git. До production-публикации GitHub Pages каталог удаляется из публикуемой ветки после переноса необходимых итоговых фактов в постоянную документацию.

## D-014. Страница `/about/` и поведение legacy URL

Статус: принято.

Это решение заменяет отложенное решение D-005 и уточняет список маршрутов из D-004.

Страница `/about/` переносится на новый статический сайт. Со старого сайта на VPS берётся только проверенный текстовый материал. Ghost-разметка, стили, JavaScript, Portal, служебные элементы, коммерческие блоки и другие визуальные механизмы старой страницы не переносятся.

Новая `/about/` создаётся в действующей визуальной системе нового сайта с повторным использованием локальных компонентов и ресурсов главной или пользовательской 404. Отдельный пункт `/about/` в навигацию главной не добавляется. Страница остаётся доступной по прямому URL и после реализации включается в sitemap.

Юридические страницы `/privacy/`, `/consent/`, `/oferta/`, блог, отдельная статья, author/tag archives, RSS и Ghost-служебные маршруты не переносятся. На GitHub Pages они используют пользовательскую 404 без нерелевантного redirect на главную.

Старый сайт `numerologpro.ru` на VPS до DNS cutover остаётся нетронутым read-only источником исходных текстов. Точкой истины целевой реализации являются GitHub-репозиторий и GitHub Pages preview.

## D-015. Единая визуальная система product pages

Статус: принято.

Product pages сохраняют собственную идентичность внутри общей визуальной системы Тихого Дома. Основные accents: синий для КвантоКода, фиолетовый для Mystic Oracle и фирменный magenta #E01CBC для ЭЛИОР.

Редизайн не меняет видимый текст, CTA, Telegram URL, SEO metadata и аналитику. Тяжёлые растровые UI-изображения и дополнительные frontend-зависимости не добавляются.

После отдельного визуального QA каждой product page шесть внешних CSS-файлов объединяются в один assets/css/site.css. Консолидация должна удалить дубли шрифтов и общих правил, изолировать page-specific selectors и сохранить подтверждённый внешний вид.

Custom domain и DNS cutover выполняются только после полного QA объединённого CSS.
